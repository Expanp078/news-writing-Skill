# alpha1.2 分析报告与写作前准备协议

这两个产物分别回答“材料和任务究竟是什么”与“在这些材料约束下准备怎样写”。前者先于经验库，后者可以利用经验库。两者都允许自由探索，不是固定篇幅的表格。

## 1. 分析报告的任务

分析报告不是新闻稿摘要，也不是把知识库条目逐条复述。它要建立一张可写作的中间地图：材料里有什么、能够证明什么、受众缺什么、可从哪些角度组织、哪些风险会改变写法。

报告可以先保留多个假设，甚至得出“当前材料不够写成用户要求的稿件”。这比过早选择一个漂亮但证据不足的角度更有用。

## 2. 建议结构

```markdown
# 分析报告

## 0. 任务元数据
- task_id / 体裁 / 媒介 / 受众 / 时点 / 长度或交付约束
- 读取资源、版本哈希、路由假设
- material_cutoff / event_time / source_publication_time / product_state / update_trigger

## 1. 材料地图
- 文件/链接/采访/数据/文件原件/画面声音
- 事实、人物、机构、时间线、空间、数字、引语
- 已知、待核、相互矛盾、无法取得

## 2. 报道对象与公共问题
- 事件或机制的变化
- 受影响群体、受众知识差、公共后果
- 不应被热度、头衔或推荐语替代的判断

## 3. Claim ledger
- claim_id / 主体 / 动作或状态 / 时点 / 范围
- 来源、独立性、证据锚点、反证、回应、证据等级
- 当前允许的语气与未决项
- source_access_level / quote_mode / procedure_state / document_title_status / approval_actor

## 4. 角度和问题候选
- 候选角度 A/B/…
- 各自的核心问题、能证明的范围、遗漏和风险
- 尚不决定的张力

## 5. 结构候选
- 状态声明、问题链、场景—机制、主题线、系列矩阵等
- 每种结构对证据和受众理解的要求

## 6. 知识库映射
- 图谱节点、综合卡、跨书原则、适用边界
- 命中的 READ_NEXT 与下钻原因

## 7. 语言、伦理和媒介风险
- 隐私、回应、匿名、未成年人、因果、称谓、术语、画面/声音证据
- 受众可能的误读和反事实

## 8. 开放问题与分析结论
- 仍需补采或确认的内容
- 当前最可行的写作方向，但不提前写成成稿
```

内容标签建议使用：`[材料观察]`、`[知识库映射]`、`[跨书推导]`、`[AI迁移]`、`[待核/不确定]`。标签是证据边界，不是写作风格。

## 3. Claim ledger 的最低字段

|字段|说明|
|---|---|
|claim_id|稳定编号，稿件和修改意见回链|
|claim|尽量拆成单一事实、数字、引语、因果或评价|
|source|原始文件、直接当事人、现场、数据、机构或二手来源|
|independence|是否与其他来源真正独立|
|status|confirmed / attributed / disputed / inferred / unknown|
|time_scope|发生、发布、生效或截至哪个时点|
|response|被批评方的回应、拒答、未联系及其限制|
|allowed_strength|标题、导语、正文允许使用的语气|
|risk|法律、隐私、伤害、误读或媒介证据风险|
|source_access_level|original / summary / prediction / unavailable|
|quote_mode|direct / attributed_indirect / prohibited|
|procedure_state|announced / scheduled / draft / submitted / adopted / effective / unknown|
|document_title_status|official_verified / source_title / editor_short_title / unknown|
|approval_actor|谁有权通过、签署、生效或确认；不清楚时写 unknown|

“来源说 X”不自动等于“事实是 X”；“发生在相邻时间”不自动等于因果；“研究或机构预计”不自动等于已经发生。

若 `source_access_level` 不是 `original`，`quote_mode` 默认不得为 `direct`。二手摘要只能归属明确地间接转述；没有可靠归属时禁止写入稿件。会议、政策和成果文件必须把 `procedure_state`、`document_title_status` 和 `approval_actor` 单列，不能用一个普通 claim 覆盖草案、提交、通过和生效。

## 4. 写作前准备的任务

写作前准备不是把分析报告再摘要一次，而是把分析转成可执行的编辑决策。它可以选择一种结构，也可以提出双轨方案，直到起草前才决定。

至少回答：

1. 这篇稿件向谁承诺解决什么问题？
2. 中心角度是什么？它比备选角度多保留了什么、舍弃了什么？
3. 哪些主张必须在首屏出现，哪些只能放到背景或解释？
4. 每段/场景/模块要完成什么证明、转折、解释或行动提示？
5. 哪些场景、细节、数据、引语和背景能降低理解成本，哪些只是装饰？
6. 经验库中的策略在当前材料上是否满足触发条件？哪些边界会使其失效？
7. 有无反例、相反证据、权力不对称或受影响者被遮蔽？
8. 何时需要补采、降级、延迟、删去或在发布后更新？
9. 有没有一个不依赖现成经验卡、但更适合当前材料的新写法？

## 5. 建议结构

```markdown
# 写作前准备

## 1. 编辑承诺
- 受众问题、中心主张、报道边界、不做的承诺

## 2. 选择与舍弃
- 选择的角度和理由
- 候选角度/结构及其被放弃或保留的原因

## 3. 结构蓝图
- 标题/导语或开头的功能
- 段落、场景、问题链或主题线的功能序列
- 每一部分的 claim、证据、来源和转场
- 结尾要回到何种公共问题或未决项

## 4. 写作部件计划
- 标题方案
- 导语/场景方案
- 关键引语、数据、背景、术语解释
- 节奏、视角、语气、媒介适配

## 5. 经验与知识调用
- 使用的 SYN/RES 策略、综合卡和下钻笔记
- 条件、边界、反模式、案例锚点

## 6. 创意决策摘要
- 假设、反例、转向、生产性张力、新洞见、尚未决定之处

## 7. 起草前检查
- 事实、证据、回应、伦理、语言、版本和发布条件
- `material_cutoff`、`product_state`、`update_trigger` 和相对日期标题的绝对日期锚点
- 二手摘要的引语降级、文件正式题名、程序状态和审批主体
```

## 6. 创意决策记录

记录简洁的外部决策摘要，不要求暴露隐性逐步思维。建议每条写成：

```yaml
decision_id: DEC-###
question: <需要决定的问题>
options: [<候选>]
evidence: [<材料或知识锚点>]
counterexample: <使某候选失效的反例>
choice_or_hold: <选择或暂缓>
reason: <可审计的简短理由>
revisit_if: <什么新材料会改变它>
```

若没有真实分岔，不要为了满足格式虚构多个选项；可以记录“单一结构已足够，原因是……”。

## 7. 起草前门槛

进入起草至少需要：

- 主张和材料边界已写出；
- 角度和结构至少经过一次比较；
- 首屏承诺不超过证据强度；
- 若使用相对日期标题，必须同时登记绝对日期和材料截点；
- 没有加载原文时不得使用直接引语；
- 草案、预告、提交、正式通过和生效不得合并为同一时态；
- 关键数字、时间、人名、引语和因果有来源或显式未决状态；
- 高风险对象的回应、隐私和伤害控制已有方案；
- 仍然存在的缺口已决定是补采、降级、延迟、删除还是发布后更新。

门槛不要求所有不确定性消失；它要求不确定性被看见、被命名、被合理地放置。
