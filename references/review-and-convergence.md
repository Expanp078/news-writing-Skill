# alpha1.1 独立检查、修订与收敛协议

检查者的任务是发现作者可能看不见的事实、结构、受众和伦理问题，并提供能改变稿件的修复方向。它不是主写作者的第二次润色，也不是把经验卡逐项套在稿件上。

## 1. 角色隔离

主写作者负责：分析报告、写作前准备、所有稿件版本、修订决策和最终整合。

每轮 `news-draft-reviewer` 使用全新上下文。它可以读取：

- 当前任务的原始材料和输入清单；
- `analysis-report`；
- 当前稿件；
- 第二轮起的上一版稿件；
- 图谱、相关综合卡、经验库相关策略和必要的下钻资源。

它在首次独立阅读阶段不能读取：

- 主写作者的写作前准备；
- 上一轮检查意见；
- 主写作者的修订日志和创意决策记录；
- 任何声称“应该怎样评价这篇稿子”的预设答案。

完成盲读后，检查者可以读取上一版检查文档，用于判断修改是否真正回应了问题。加载清单写入检查文档。

## 2. 每轮检查方式

### 2.1 先建立自己的文章模型

检查者先用自己的话回答：稿件试图解决什么问题、向谁承诺什么、用什么证据支撑、读者可能在哪里误读。若这一步无法完成，先指出稿件的角度/结构问题，不要立即改句子。

### 2.2 自由选择检查重点

可以从以下方向选择，但不要求每轮逐项覆盖：

- 事实、来源、数字、时间线、引语、因果和主张强度；
- 角度、公共意义、受众知识差和被遮蔽的群体；
- 首屏承诺、结构发动机、信息顺序、转场、节奏和结尾；
- 场景、细节、数据、专业解释与总体命题的关系；
- 语言、句法、术语、称谓、媒介适配和可理解性；
- 公平、回应、隐私、未成年人、创伤、安全和发布后责任；
- 稿件是否过度套用经验，是否出现新的、更合适的写法。

检查者可以完全改变检查角度，例如从“结构不成立”转向“主张本身不成立”，也可以决定某一方面已经无需再审。

### 2.3 再做与上一版的差异核对

第二轮起必须比较当前稿与上一稿，但差异不是字符数：

- 哪个主张、证据关系、段落功能或读者承诺改变了；
- 上一轮问题是被解决、规避、转移还是只换了词；
- 修改是否引入新事实、逻辑、伦理或媒介问题；
- 稿件是否更接近材料可以证明的范围。

## 3. 严重度

- `P0`：事实错误、编造、严重安全/隐私/法律风险，或会使稿件不能交付；
- `P1`：中心角度、关键证据、结构、受众理解、回应权或重要边界存在实质缺陷；
- `P2`：明显降低准确性、清晰度、节奏或解释效果，但不阻断交付；
- `P3`：局部措辞、标题、句法或可选优化；
- `observation`：值得保留的观察，不一定需要修改；
- `challenge`：检查者认为当前经验/准备方案可能错误或过窄；
- `novel_candidate`：可迁移的新机制或新结构候选，尚未成为稳定规则。

每条意见必须有稿件位置、证据/知识依据、后果和修复方向。可以给出多个修复方向，但不代替主写作者直接重写整篇。

每轮检查文档末尾必须单独写：

```yaml
unresolved_p0_p1: 0
```

如果仍有 P0/P1，填写数量并列出对应 finding ID；不能用“总体不错”或“建议继续关注”代替。涉及二手摘要时，检查者必须确认 `source_access_level` 和 `quote_mode`；涉及会议、政策或成果文件时，必须确认 `procedure_state`、`document_title_status` 和 `approval_actor`。

## 4. 检查文档模板

```markdown
# review-rN

## 元数据
- task_id / round / reviewer_id / 当前稿哈希 / 上一稿哈希
- 实际加载的资源和盲读边界

## 独立文章模型
- 报道问题、受众承诺、证据形状、公共风险

## 主要优点
- 说明哪些决定有效，为什么有效

## 发现
### Rn-001 [P1|P2|...]
- 位置：
- 问题：
- 依据：
- 后果：
- 修复方向：
- 置信度：

## 可选的新角度或结构
- alternative / challenge / novel_candidate

## 与上一版的实质差异
- solved / moved / unchanged / newly_introduced

## 未决问题

## 收敛判断
- continue | no_material_change | blocked
- 判断理由：
```

## 5. 修订协议

主写作者收到检查意见后，不必逐条照做，但必须对每条 P0/P1 和 `challenge` 留下处理记录：

```yaml
finding_id: Rn-001
decision: accepted|partially_accepted|rejected|deferred
change: <修改了什么，或没有修改什么>
reason: <证据和编辑判断>
new_risk: <若有>
```

结构、角度、材料取舍和叙事发动机都可以重做；如果上一轮问题来自错误的问题定义，允许回到分析报告或写作前准备重新选择。拒绝意见不能只写“个人偏好不同”。

## 6. 收敛判断

第一版之后至少完成三轮检查和修订。第三轮之后才允许判定收敛，且必须同时满足：

1. 检查者明确写 `no_material_change`，说明最新稿与上一稿在问题、证据、结构和受众承诺上没有实质差异；
2. 没有未处理的 P0/P1；
3. claim ledger、来源状态、回应与不确定性没有新的阻断缺口；
4. 主写作者确认终稿没有超出材料可证明的范围。

以下情况不能判定收敛：只改了标点/同义词但中心问题仍错；检查者因为看不到准备文档而漏掉关键材料；稿件表面变化很大但仍未解决同一根因；材料本身不足以承担原定承诺。

如果连续两轮只产生表面修改，下一轮必须主动改变问题定义、证据排序、结构候选或受众假设。若检查者反复发现材料缺失，应转为 `blocked` 或交付“可写范围稿”，不能靠更多轮次制造确定性。

## 7. 最终清理

收敛后复制最新稿到 `final/final.md`，清除“第几轮”“检查意见”“经验卡编号”等内部痕迹，但保留必要的来源归属、截至时点和不确定性。内部产物和版本链继续保留，供 AI 后续复盘。
